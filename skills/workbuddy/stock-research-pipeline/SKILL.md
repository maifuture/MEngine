# 股票研报流水线（stock-research-pipeline）

## 这个技能解决什么

用户扔来一个股票名字或代码（如「华明装备」「002270」），要一条从**一手财报**到**卖方研报**再到**可证伪的操作框架**的完整链路。市面上要么只给财报数字、要么只转述研报，缺的是把两者对齐并指出「口径打架在哪、折价在定价什么」。

本技能把这条链路固化成六步，每步都有可执行脚本和已知的坑。

## 何时使用

- 用户给出股票名称/代码 + 「分析一下」「研报」「收入靠什么」「属于什么板块」「近期有没有研报」「给个短期中期看法」
- 用户要求复现「财报 → Top2 收入 → 行业概念 → 个股研报 → 行业研报 → 短中长期指引」这条固定流程
- 用户点名巨潮资讯（cninfo）或新浪财经研报频道作为数据源

不适用：只要一个数字（PE、股价）的查询；港美股（本流程的巨潮与新浪研报检索仅覆盖 A 股）。

## 前置：加载方法论

本技能负责**取数与流程**；分析质量由金融方法论 reference 保证。开工前按场景加载 `workbuddy-finance-skill` 的对应 reference：

- 个股研究：`stock-deep-research.md` + `valuation-pricing.md`
- 若用户明确要操作节奏：追加 `trade-plan.md`
- 产出 HTML 前：`html-report-style.md`（本技能的 `assets/report-shell.html` 已内化其核心约束，可直接复用骨架）

## 六步流程

> **命令约定（跨平台）**
>
> - `python3` 指本机 Python 3 解释器。**Windows** 上改用 `python` 或 `py -3`，路径分隔符用 `\`。
> - 命令在本 skill 的 base 目录执行，产物用 `--outdir` 指到工作目录。PDF 解析需 `pdfplumber`（缺失时回退 `pypdf`）。

### Step 0 · 解析标的

用户给名字还是代码都行，`topSearch` 接口两者通吃。先确认是 **A 股上市主体**（同名公司、ADR、ETF 要排除），并把 `code / 简称 / orgId` 三个值记下来，后面每一步都要用。

```bash
python3 scripts/cninfo_periodic.py list --code <名字或代码>
```

### Step 1 · 最新定期报告与 Top 2 收入来源（一手）

```bash
python3 scripts/cninfo_periodic.py fetch --code 002270 --outdir ./reports
```

脚本会：解析 orgId → 翻页拉定期报告列表 → 取最新一期 → 下载 PDF → 转全文 txt → 打印「主要会计数据和财务指标」「营业收入构成」两个章节。

判定 Top 2 的规则（**必须遵守，详见 `references/report-blueprint.md` 第二节**）：

1. 只用**分产品**口径，不用分行业、不用分地区
2. 「其他」不参与排名
3. 每项必须同时给**收入占比 + 毛利率 + 同比**，否则无法判断谁决定估值
4. 归零/退出的业务要点名（它常是毛利率变动的解释项）
5. 出口是电力设备内部的**地域拆分**，不是独立业务板块

**必做的时效校验**：按当前日期推算「理论上应已披露的期次」（4 月底前有年报+一季报，8 月底前有半年报，10 月底前有三季报），与检索结果比对。若最新一期缺失（如 10 月下旬三季报未出），在报告里写明**未披露 + 法定截止日**，且**不对未披露期做任何推算**。

### Step 2 · 行业与概念板块

用 `domain_search` 工具取（一句话意图，如「研究 A 股华明装备的整体情况」），能一次拿到申万三级链条 + 概念标签 + 行情估值。也可用 `scripts/sina_reports.py codes` 查申万二级行业代码。

输出要求：申万三级链条（可核验的硬分类）+ 概念按属性分组（核心产业 / 第二业务 / 电源侧外延 / 资质与交易属性），每个概念挂一行「映射到哪块业务、什么产品/事件支撑」。

### Step 3 · 个股研报（近 3 个月）

```bash
python3 scripts/sina_reports.py company --code 002270 --months 3 --outdir ./reports
```

**若返回 0 篇 → 直接进 Step 5 的终止分支。**

### Step 4 · 行业与概念板块研报（近 3 个月）

先用 Step 1 的 Top 2 业务反推关键词（如「电网,变压器,特高压,输变电」＋第二业务的「机床,数控」），再抓：

```bash
python3 scripts/sina_reports.py industry --keywords 电网,变压器,特高压 --months 3 --outdir ./reports --download 8
```

脚本走两条路径并合并去重：① 行业研报频道倒序翻页（覆盖广，但**最多回溯约 1 个月**）；② 标题关键词检索（能挖更早月份，但条数少）。脚本会打印「频道遍历最早到哪天」，并在窗口未被完全覆盖时给出警告。

**这条警告必须原样反映到报告里**：写成「在库可匹配篇目 + 回溯边界」，不得表述为「全部研报」，也不得因抓不全而谎称「无近期研报」。

### Step 5 · 终止分支

- 个股与行业**都**查不到研报 → 正文只回一句「**无近期研报**」，说明检索窗口与数据源，然后结束。不出 HTML、不做延伸分析、不给买卖框架。
- 只有一侧有 → 正常出报告，但在第四章标明另一侧为空及其原因（覆盖边界 vs 确实没有）。

### Step 6 · 归纳 + 短中长期指引 + 交付

按 `references/report-blueprint.md` 的章节结构写 HTML，骨架直接用 `assets/report-shell.html`（纯内联样式、零外部依赖、无 `<script>`）。

写指引的三条硬约束：

1. **三段式**：每段都要「看什么 → 什么条件下成立 → 什么条件下推翻」，禁止「长期看好」这类无证伪条件的句子
2. **禁止指令式结论**：不给买/卖/加仓，不给单一点位目标价；给估值区间 + 三情景（悲观/中性/乐观 × 给定 PE × 对应股价 × 触发条件）
3. **说清赚什么钱**：现价相当于哪个情景的百分之多少，赔率来自业绩还是估值

另需两个附加章节（缺了结论会悬空）：

- **口径校验**：券商笔误、报告期缺口、研报覆盖边界，逐条列明并说明本报告采用哪个口径
- **风险分层**：短期/中期/长期，每条风险写机制 + 已有证据（数字或公告）

**最后一章给的是原文出处（外部原始链接），不是本地文件**（放在免责声明之前）：下载了几份财报和研报，就列出几份，逐份链到**上游站点的原文页**。链接不要手写（rptid、公告 ID、日期，手敲必错必漏），统一用脚本扫目录生成：

```bash
python3 scripts/build_index.py --dir ./reports --check     # --check 会逐条探测 HTTP 200
```

脚本输出整块「九、原文出处（外部原始链接）」章节，粘进报告即可。链接来源：

| 类型 | 原始链接从哪来 |
|---|---|
| 研报 txt | 文件头部第 4 行 `来源：https://stock.finance.sina.com.cn/.../rptid/<id>/index.phtml`（`sina_reports.py` 落盘时写入） |
| 财报 PDF | 同目录 `sources.json` 的 `pdfUrl` / `detailUrl`（`cninfo_periodic.py fetch` 时自动写入，含 announcementId、orgId、页数） |

**为什么指向外部原始出处，而不是本地文件**：报告会在三种宿主里被打开，实测结论如下。

| 打开方式 | 外部原始链接 | 本地相对链接 | `file://` 绝对链接 |
|---|---|---|---|
| 本机双击（origin = `file://`） | ✅ | ✅ | ✅ |
| 以项目目录为根的本地 http 服务 | ✅ | ✅ | ❌ 浏览器禁止 http→file 导航 |
| 内置预览面板（`/static-html/<hash>/` 单文件） | ✅ | ❌ 404 | ❌ 被 CSP 拦 |

内置预览面板**只提供那一个 HTML 文件**，同级 `reports/` 目录不暴露（`/`、`/reports/` 均 404），响应头 `Content-Security-Policy: default-src 'self' …` 也不含 `file:`。所以本地链接在面板里必然点不开，**换多少种写法都没用**。改指外部原始出处后，三种宿主下全部可点，也不依赖本地目录是否被暴露。代价是需要联网 —— 若明确要求离线可读，用 `--link-mode relative`，并说明该模式在预览面板里无效。

清单条数要与第三、四章的研报篇数一致，不一致说明有下载失败被静默吞掉。

全文末尾原样附免责声明（模板见 `references/report-blueprint.md` 第七节），不得改写或省略。

## 交付前自检

- [ ] 最新报告期是否正确，未披露期次是否已标注且未推算
- [ ] Top 2 是否用分产品口径、是否附毛利率与同比、「其他」是否已排除
- [ ] 每个关键数字是否就近标注了来源 + 时点（不要只在文末放总来源）
- [ ] 研报是否逐篇列了日期/机构/观点，再归并共识与分歧（不要只给综述）
- [ ] 分歧是否落到「乐观一侧 vs 谨慎一侧」两列，而不是平铺
- [ ] 行业研报的覆盖边界是否写明
- [ ] 报告结尾是否有**原文出处清单**（财报 + 全部研报，逐份可点）；条数是否与第三、四章篇数对得上；链接是否指向**外部原始页**（`static.cninfo.com.cn` / `stock.finance.sina.com.cn`），而不是本地路径或 127.0.0.1
- [ ] 是否跑过 `build_index.py --check`（或等价手段）实测每条链接 HTTP 200，且页面含正文而非失效提示页
- [ ] 是否**没有**把研报正文内嵌进 HTML（用户明确要求取消内嵌，报告保持可读篇幅）
- [ ] 指引是否条件化、是否给了三情景、是否说了赚业绩钱还是估值钱
- [ ] 免责声明是否原样保留
- [ ] HTML 是否无 `<script>`、无 CDN 依赖（离线可开）；若手写了 SVG 折线，检查 y 轴公式方向（写反会上下颠倒）

## 目录结构

```
stock-research-pipeline/
├── SKILL.md
├── scripts/
│   ├── cninfo_periodic.py    # 巨潮：代码/简称 → orgId → 定期报告列表 → PDF → 收入构成
│   ├── sina_reports.py       # 新浪：个股研报 / 行业研报 / 申万行业代码表
│   └── build_index.py        # 扫 reports/ 生成第九章「原文出处」外链清单（含 --check 探测）
├── references/
│   ├── data-sources.md       # 接口参数、GB2312 编码坑、60 页回溯上限、type 过滤失效
│   └── report-blueprint.md   # Top2 判定、归并法、指引写法、口径校验、原文出处规则、HTML 规范
└── assets/
    └── report-shell.html     # 单文件内联样式骨架，已含原文出处区块模板
```

依赖：`pip install pdfplumber`（仅 PDF 解析需要，缺失时自动回退 `pypdf`）。三个脚本只用标准库 + PDF 库，不需要 requests。

`reports/sources.json` 是财报外链的来源（`cninfo_periodic.py fetch` 自动写）；缺它时第九章的财报行会降级为纯文本并标红「未取到原始链接」，不会生成死链。

## 已知的坑（动手前先看，能省一轮返工）

1. **巨潮 `type=category_ndbg_szsh` 过滤会被服务端忽略**，永远返回最近 30 条全量公告 → 必须翻页 + 本地按标题正则筛。
2. **定期报告有两套标题写法**：`2026年一季度报告` 与 `2026年第一季度报告` 都真实存在，正则要写成 `年第?一季度报告`。
3. **新浪是 GB2312**：中文查询参数必须按 GBK 编码后再 urlencode，否则一律返回「没有找到相关内容」，极易误判成「无研报」。
4. **新浪行业研报列表分页参数是 `p` 不是 `page`**；且最深约 60 页（回溯约 1 个月）。
5. **`t1=3&industry=sw2_xxxxxx` 筛出来的是个股研报，不是行业研报**（类别全为「公司」）。
6. **研报之间会互相打架**：直接/间接出口增速互换、净利率口径混淆都真实遇到过。以财报 PDF 原文为准，差异写进「口径校验」章节，不要静默取一个。
7. **第九章一律指外部原始出处，不要做本地文件链接**。内置预览面板只提供单个 HTML（`/static-html/<hash>/`），同级 `reports/` 返回 404，响应头 CSP 也不含 `file:` → `file://`、相对路径、127.0.0.1 三种写法在那个面板里全部点不开。曾按「换链接写法」的思路改了三轮（相对 → file:// → 绝对 → 内嵌正文）才确认根因是**宿主不提供文件**，不是 href 格式。最终方案：链接直指上游原文页（新浪 `rptid` / 巨潮公告 ID），三种宿主下都可用。也不要为了兜底把正文内嵌进 HTML —— 用户明确不要内嵌，报告会从 88 KB 膨胀到 180 KB。
