# 交付物蓝图：从研报到短中长期指引

本文件规定**报告里该写什么、不该写什么**，以及每个判断的判定规则。SKILL.md 只管流程，判断口径看这里。

---

## 一、六步与交付章节的对应

| 用户步骤 | 报告章节 | 硬要求 |
|---|---|---|
| 1 最新财报 + Top 2 收入来源 | 一、最新定期报告与 Top 2 收入来源 | 必须写明报告期、披露日、PDF 来源；必须给「分产品」原表数字 |
| 2 行业与概念板块 | 二、行业与概念板块归属 | 申万三级链条 + 概念分组，每个概念要能挂到 Top 2 业务上 |
| 3 个股研报 | 三、个股研报 | 逐篇列表（日期/机构/观点/预测），再做共识与分歧归并 |
| 4 行业研报 | 四、行业与概念板块研报 | 逐篇列表 + 「对公司的传导」一列；必须标注覆盖边界 |
| 5 无研报则终止 | —— | 若个股与行业**都**无研报 → 正文只回「无近期研报」，不出 HTML，不做延伸分析 |
| 6 归纳 + 短中长期指引 | 五、股价与估值 + 六、短/中/长期指引 | 三段必须条件化（看什么→什么条件成立→什么条件推翻） |

补充章节（强烈建议，缺了会显得结论悬空）：

- **七、真正可能伤害股价的因素** —— 按短期/中期/长期分层，每条写机制 + 已有证据（数字或公告）
- **八、口径校验与数据缺口** —— 券商笔误、报告期缺失、覆盖边界，逐条列明
- **九、原文出处（外部原始链接）** —— 财报与全部研报逐份链到巨潮 / 新浪原文页，见 7.1「原文出处区块」

## 二、Top 2 收入来源的判定规则

1. **只用「分产品」口径**，不用「分行业」，不用「分地区」。
2. **「其他」不参与排名**：占比通常 <5%、无业务实质，即使排第二也不作为「收入来源」。
3. **归零/退出的业务要点名**：如「电力工程本期收入 0、上年同期 2,386 万元」，退出对毛利率是正向贡献——这是解释「营收增长与毛利率变动不同向」的关键，不写会被追问。
4. **必须附毛利率与同比**：只有收入占比没有毛利率，无法判断哪块业务决定估值。高毛利小占比业务（如 11% 收入 + 23% 毛利）和低毛利大占比业务的经济含义完全不同。
5. **出口不是业务板块**：直接/间接出口是电力设备内部的销售地域拆分。用户若问「第二收入来源是出口吗」，需明确否定并说明口径差异。

## 三、行业与概念的映射纪律

- 先给**申万三级链条**（一级 → 二级 → 三级），这是可核验的硬分类。
- 概念按**属性分组**，不要罗列十几个标签：核心产业概念 / 第二业务概念 / 电源侧外延 / 资质与交易属性。
- 每个概念给一行「映射逻辑」，写清它对应哪块业务、什么产品、什么事件支撑（如「±800kV 特高压直流工程批量投运」→ 特高压）。
- 概念标签不同数据商不一致时取**交集**，并注明「不同数据商概念标签数量略有出入」。

## 四、研报归并的方法

**先逐篇列，再归并**，不要直接给一段综述——用户要能追溯是哪家说的。

逐篇表字段：`日期 | 机构 | 标题要点（一句话，抓该篇区别于他篇的点）| 盈利预测 / 目标价 / 评级`。

归并分两块：

1. **共识（几乎无争议的）** —— 通常 4—6 条，每条要有数字支撑。例：「出海是唯一增长引擎：直接 2.25 亿 / 间接 2.25 亿，合计 +44.6%，占该业务收入 >40%」。
2. **分歧（只有 2—3 处，但都关键）** —— 用「乐观一侧 vs 谨慎一侧」两列表述，比「有的说 A 有的说 B」有信息量。
   - 典型分歧：盈利预测下修幅度、对国内业务是节奏性还是结构性的判断、目标价锚（倍数 vs 绝对价）。
   - **注意**：目标价集体下调本身是信息（估值中枢下移），不只是盈利下修的结果。

**要做预期差，不要只做共识复述**。至少写一条「市场已定价什么 / 尚未定价什么」，并落到具体机制（一次性费用、复购型收入、0→1 的份额爬坡）。

## 五、短中长期指引的写法（最容易写坏的一段）

### 禁止

- 不给「买/卖/加仓/减仓」的指令式结论
- 不给单一目标价点位预测（可给估值区间 + 情景）
- 不写「长期看好」「值得关注」这类无证伪条件的句子

### 必须

**每段三段式**：`看什么（观察变量）→ 什么条件下这个判断成立 → 什么条件下被推翻`。

- **短期（1—3 个月）**：锚定**最近的一个可验证事件**（如即将披露的季报、回购进度、月度出口数据）+ 技术位置（均线、BOLL、压力/支撑位、KDJ 钝化）+ 资金面（主力 5/10/20 日净流入流、融资净买卖、北向/十大股东变动）。结论通常是「修复 or 反转」的区分，而不是方向预测。
- **中期（6—12 个月）**：锚定 2—3 个**核心变量**（订单增速、政策落地节奏、费用基数），给一致预期区间 + 当前 PE 相对板块的折溢价，再给**三情景表**（悲观/中性/乐观 × 给定 PE × 对应股价 × 触发条件）。必须写一句「现价相当于哪个情景的百分之多少」，把赔率讲清楚。
- **长期（2—3 年）**：给一句**可证伪的本质判断**——「买这家公司本质上是买 ____」。再给 2—3 条支柱，以及**一条最关键的验证指标**（走不通则估值中枢应下移到多少倍）。

### 情景测算的口径

- EPS 用「一致预期归母 ÷ 总股本」，并注明是均值还是某家。
- PE 倍数区间要说明参照系（板块当前 PE、可比公司、历史中枢），不要凭感觉给 15/20/25。
- 明确「赚业绩钱还是赚估值钱」，并给出量级（如「业绩钱只有 10%—18%，主要赚估值收敛」）。

## 六、口径校验清单（逐条过，缺一条就可能翻车）

1. **报告期是否最新**：当前是否已过法定披露期？未披露要写明「三季报尚未披露，法定截止 X 月 X 日」，且**不对未披露期做任何推算**。
2. **同比 vs 环比**：券商常混用。Q2 单季同比与 H1 累计同比必须标清。
3. **归母 vs 扣非 vs 剔除股份支付**：三个数都可能有，且都能叫「净利润」。剔除股权激励的口径要写明「剔除 X 万元股份支付影响后」。
4. **净利率口径**：归母净利率 = 归母 / 营收；含少数股东损益的净利率更高。发现某家研报的净利率与财报口径差一倍，几乎一定是口径或笔误 → 弃用并标注。
5. **直接出口 vs 间接出口增速**：两家券商可能互换（实测遇到过），以财报/多数券商一致口径为准。
6. **PE 口径**：TTM / LYR / 前瞻，三者差异大，标明用的是哪个。
7. **PB 横向比无意义的前提**：若公司 ROE 显著高于行业（如 21.7% vs 2.25%），PB 溢价是合理的，必须写清，不能简单说「PB 高于行业=贵」。
8. **研报覆盖边界**：行业研报用了哪几条检索路径、回溯到哪一天、可能漏什么，一句话讲清。

## 七、HTML 交付规范（用户偏好单文件离线）

- **单文件、纯内联样式、零外部依赖**：不引 CDN、不写 `<script>`。这样断网也能开，且不存在 JS 语法失配导致整页空白的问题。
- 首屏必须**结论先行**：核心结论块（5 条编号）+ 4 张数据卡（收入/利润/估值/目标价）。
- 图表：
  - 趋势线（股价）用**手写 SVG polyline**，坐标先算好再贴（`y = y_bottom - (v - v_min)/(v_max - v_min) * (y_bottom - y_top)`，注意 y 轴向下为正，公式方向写反会把图上下颠倒）。
  - 占比/对比用**CSS 宽度条**，比 SVG 省事且不会错。
  - 关系/传导链用 SVG 或 CSS 盒子。
- 表格：`border-collapse:collapse` + `#eef1f6` 表头 + `#eceff3` 分隔线；关键行用浅红底 `#fdf6f6` 突出。
- A 股语境**红涨绿跌**（涨用 `#c0392b`，跌用 `#1a9c6b`）。
- 每个数据块**就近标注来源 + 时点**，不要只在文末放一个总来源。
- 全文最后必须原样附免责声明（见下），不得改写、缩写或省略。

### 7.1 原文出处区块（报告结尾必须有，链接指外部原始页）

报告最后一章不能只写「已留档于 reports/」，必须给出**逐份可点击的原文出处**，让用户看完结论能直接回到一手来源核对。

**生成方式：不要手写链接**（rptid、announcementId、日期，手写必错、必漏）。统一用脚本扫目录生成 HTML 片段再粘贴：

```bash
python3 scripts/build_index.py --dir ./reports --check
```

脚本输出整章「九、原文出处（外部原始链接）」：按 `一手财报 / 个股研报 / 行业研报` 三组表格，每行「日期 + 标题（外链）+ 机构简称 + 站点·rptid」。`--check` 会逐条请求验证 HTTP 200 且页面含正文。

**硬性规则**：

1. **链接指向外部原始页，不用本地路径**。三种宿主实测：本机双击 ✅、目录根 http 服务 ✅、内置预览面板 ✅ 全部可用。而本地链接（`file://` / 相对路径 / 127.0.0.1）在内置预览面板里必然 404 —— 那个面板只服务 `/static-html/<hash>/` 下的单个 HTML，`/reports/` 返回 404，响应头 `Content-Security-Policy: default-src 'self' …` 也不含 `file:`。**这是环境限制，换多少种 href 写法都没用，别在格式上反复试。**
2. **研报链接来自 txt 头部 `来源：` 行**：`sina_reports.py` 落盘时写入 `https://stock.finance.sina.com.cn/stock/go.php/vReport_Show/kind/{search|industry}/rptid/<id>/index.phtml`。若该行缺失，脚本标红「未取到原始链接」，不生成死链。
3. **财报链接来自 `reports/sources.json`**：`cninfo_periodic.py fetch` 自动写入 `pdfUrl`（`https://static.cninfo.com.cn/finalpage/<日期>/<announcementId>.PDF`）与 `detailUrl`（公告详情页）。财报行给两个链接：标题 → PDF 直链，右下小字给「公告详情页」+「PDF 直链」。
4. **必须实测链接**。生成后跑 `--check`（或自行 curl），确认每条 200 且返回体 > 5 KB（新浪失效页通常只有几 KB，只用状态码判断会漏）。报告导语里写明「全部 N 条链接于 YYYY-MM-DD 逐条实测」。
5. **不要把研报正文内嵌进 HTML**。用户明确要外链而非内嵌；内嵌会让 88 KB 的报告膨胀到 180 KB，且与「给原文出处」的目的重复。要离线可读时才用 `--link-mode relative`，并在报告里说明该模式在预览面板内无效。
6. **只列真实存在的文件**。脚本扫目录天然满足；若手工增删过文件，重新跑一次脚本，别留死链。
7. **一份不漏**：下载了几份就列几份。清单条数应与第三、四章的研报篇数一致（财报 1 份 + 个股 N 份 + 行业 M 份），不一致说明有下载失败被静默吞掉。
8. **分组 + 倒序**：财报单独一组（它在最上面，因为是一手来源）；研报按日期倒序。
9. **标题用研报原文标题**，不要用文件名。文件名里的 `行业_` 前缀、`rptid` 是内部标识，不该出现在读者眼前。
10. **机构名用市场通用简称**（`中信建投证券股份有限公司` → `中信建投`，`中国国际金融股份有限公司` → `中金公司`），否则长标题 + 长机构名会把整行挤成两行，视觉散乱。
11. 在区块开头说明**链接指向哪里**（巨潮公告原文 / 新浪研报频道原文页）+ **失效时的检索方式**（股票代码 + 标题，或 rptid）。
12. 报告结尾的 summary 一行（生成时间/数据来源那行）仍保留，链接区块放在免责声明**之前**。若页脚原写「无外部依赖」，改成「第九章为外部原始链接（需联网）」，不要留下与实际不符的表述。

> **免责声明**：以上内容基于公开数据和量化分析，仅供参考，不构成投资建议。市场有风险，投资需谨慎。任何投资决策应结合个人风险承受能力、资金状况和投资目标独立判断，必要时咨询持牌专业机构。过往表现不预示未来收益。
