# 巨潮公告抓取与短期影响研判

把"某只票今天发了什么公告、对股价算什么"变成一条可复现的流水线：定口径 → 抓取 → 分诊 → 读原文 → 对齐行情 → 定级 → 出报告。当日无公告时，流程在"抓取"之后即止。

三条核心纪律：

1. **评级建立在公告原文的数字与行情实际反应之上，不建立在标题上。**
2. **财报类文件不在这里评。** 业绩预告、业绩快报、季度/半年度/年度报告及其摘要，一律转交 `earnings-report-deepdive`。
3. **无公告就说无公告，但反证不能省。** 当日 0 条先反证接口是否正常，确认后一句话结束——不扩窗、不取行情、不给级、不补分析。

## 执行流程

> **命令约定（跨平台）**
>
> - `python3` 指本机 Python 3 解释器。**Windows** 上改用 `python` 或 `py -3`；若本机有专用虚拟环境，换成该环境解释器的绝对路径。
> - `<skill_dir>` 指本 skill 的 base 目录（加载时会给出）。Windows 上路径分隔符用 `\`。
> - 命令在**工作目录**执行，输出落在当前目录，不要写进 skill 自己的目录。
> - Windows 终端若中文乱码，先设 `set PYTHONIOENCODING=utf-8`（PowerShell：`$env:PYTHONIOENCODING="utf-8"`）再跑。

### 0. 定口径：默认当日，最多一个月

| 模式 | 触发条件 | 检索窗口 | 分析对象 |
|---|---|---|---|
| **默认：仅当日** | 用户没有明确说时间范围（绝大多数情况） | `--days 1` | 今天披露的公告 |
| **近期：一个月** | 用户明确说"最近""近期""这几天""本周""上周""昨天""这段时间有什么公告" | `--days 30` | 最近一个自然月内披露的公告，重点看用户点名的日期 |

- **不许自作主张扩窗。** 当日 0 条就是 0 条，不要"顺手往前查 4 天看看有没有漏掉的"，也不要"今天没有就看看最近的"。扩窗是用户的要求，不是你的判断。
- **窗口硬上限一个月。** 用户要求更长区间时，说明本 skill 只在一个月内作业，按其要求的最近一个月执行并标注截断；确实需要更早的公告，要求用户指定具体区间后分批（每批 ≤ 1 个月）处理，不要一次拉半年。
- **当日 0 条：先反证，再收工。** 反证必做（脚本已自动执行，失败时手动补跑，见 1.2）；反证通过后直接回「当日无公告」，不扩窗、不取行情、不给评级、不出报告、不推测原因。
- 当日是周末或节假日时，公告照常披露但市场无法反应，行情对齐要取其后首个交易日；不得用披露日当天（无交易日）的行情解释影响。反之，今天是周一而用户只问"今日公告"时，周末那批不在窗口内——要覆盖就让用户明确说"最近几天"。

### 1. 定位标的并抓公告

#### 1.1 检索

```bash
# 当日模式（默认）
python3 <skill_dir>/scripts/cninfo_fetch.py --symbol 688825 --days 1 --out ./cninfo_688825

# 近期模式（用户明确要近期公告时，一个月窗口）
python3 <skill_dir>/scripts/cninfo_fetch.py --symbol 688825 --days 30 --out ./cninfo_688825
```

- 只有名称没有代码时用 `--keyword 长鑫`，脚本会打印全部命中项，**多个同名标的手动确认 code**，不要默认取第一条。
- 指定更窄区间：`--start 2026-10-01 --end 2026-10-24`（区间同样不得超过一个月）。
- 只想看清单不下载：`--no-download`。
- 脚本会把 PDF 与提取出的 `.txt` 落到输出目录，并生成 `announcements.json`。
- 若报 `pypdf 未安装`：`python3 -m pip install pypdf`（Windows 用 `python -m pip install pypdf`）。

脚本会自动给出四类提示，务必读：① 无实质性公告 ② 混入 H 股/港股例行披露 ③ 存在非交易日披露 ④ 文本过少疑似扫描件。

**A+H 公司的坑**：中芯国际、比亚迪、宁德时代这类 A+H 标的，公告列表里会混入大量"H股公告／翌日披露报表／证券变动月报表"。这些多为与 A 股同步的重复信息，脚本已单独标记为 `H股披露`，不要当成新增事件去解读。

**披露稀疏是常态**：部分公司（白酒、银行、公用事业）一天零公告、一个月零公告都正常。当日 0 条不代表异常，按 1.2 收工；**不要靠扩窗来自证**，也不要为了"再确认一下"多跑几次不同窗口。

#### 1.2 当日 0 条：先反证，再一句话收工

**反证必做，不可省。** 目的是把"公司确无披露"与"接口没打通／代码错配"区分开——不反证就报"无公告"，有可能把"查不到"说成"没发公告"。

0 条时脚本会自动查一次全市场当日公告总数，输出这样的块：

```text
-- 无公告 --
  * 2026-10-24（周六）无公告。默认口径为仅当日。
  * 接口自检：全市场 2026-10-24 共 2039 条 → 反证通过，接口正常，公司确无披露。
  结论：直接回复「当日无公告」并结束，不再做进一步分析。
```

**情况 A：自检正常**（全市场数百至数千条）→ 反证通过，进入下面的收工流程。

**情况 B：自检失败或全市场亦为 0 条** → 手动补跑一次反证，不要直接下结论：

```bash
# 查询全市场某日公告总条数；省略日期则为今天
python3 <skill_dir>/scripts/cninfo_fetch.py --verify-market 2026-10-24
```

输出 `全市场 2026-10-24 共 N 条`，并给退出码：`0` 接口正常且有公告、`1` 接口正常但全市场 0 条（疑似非交易日）、`2` 请求失败或日期非法。

补跑后仍失败（退出码 2）、或全市场确实为 0 条（退出码 1） → 结论只能写成「未能从巨潮确认今日公告，疑似接口异常或非交易日」，**不断言公司没披露**，到此为止，不再重试第三次、不再换标的试探。

反证只判断接口是否正常：**不写进结论、不参与评级、不作为"公司信息披露平稳"之类的判断依据。**

**反证通过后，一句话收工。** 回一句「{名称}（{代码}）今日无公告」即结束。以下动作一个都不要做：

- 取行情、做涨跌归因——没有事件可归因
- 给评级（**包括"中性"**）——评级对象不存在
- 生成 HTML、调 `present_files`、存 PDF
- 扩窗回看昨日／周末／上周，去找"其实有公告"
- 预告下一件大事、推断下一份财报披露日期
- 补行业背景、估值讨论、"值得持续关注"这类填充段

近期模式 0 条同理：先反证，再一句话说清"起止日窗口内无公告"，不扩窗、不出报告。

### 2. 分诊：财报类直接转交

抓完先按标题分诊，**这一步决定后面全部动作**，不要跳。

| 命中标题 | 处理 |
|---|---|
| 业绩预告（含"业绩预增／预盈／预减／预亏"变体、"自愿性披露公告"后缀） | → 转交 `earnings-report-deepdive` |
| 业绩快报 | → 转交 `earnings-report-deepdive` |
| 第一季度报告 / 第三季度报告（含"三季度"写法） | → 转交 `earnings-report-deepdive` |
| 半年度报告 / 年度报告 | → 转交 `earnings-report-deepdive` |
| 上述报告的**摘要** | → 转交 `earnings-report-deepdive` |

判定口径与 `earnings-report-deepdive` 的 `is_earnings()` 保持一致：核心词 `业绩预告|业绩快报|业绩预[增盈减亏]|季度报告|半年度报告|年度报告`，再剔除英文版、更正件、说明会、会计师专项说明等衍生件。**拿不准就走财报 skill——宁可转交，也不要在本 skill 里给财报评一个级。**

**不转交**（走本 skill 正文）：业绩预告更正公告、业绩说明会通知、会计师事务所关于业绩预告的专项说明、产销／经营数据快报（这属经营数据，不是财报）。

**近期模式下命中的财报类**：如果不是今天披露的，转交时要点明"这不是当日披露"，让 `earnings-report-deepdive` 走它的最新模式（`--latest`），并在结论里标注披露日与距今天数。不能把 6 天前的业绩预告当今天的新闻来写。

**转交后的分工，三种情形：**

1. **当日只有财报类** → 本 skill 到此结束，不读原文、不取行情、不出报告、不给评级，由 `earnings-report-deepdive` 接管全流程。
2. **财报 + 非财报公告同日出现** → 先跑 `earnings-report-deepdive` 出主报告；本 skill 只对非财报公告给出方向与五级判断，**并入财报报告里的一节**，不另生成第二份 HTML。同一只票两份报告互相打架，比少一份严重。
3. **非财报公告属重大事件**（重组、处罚立案、停牌复牌、控制权变更、重大合同） → 即使当天有财报，也必须在主报告里单列一节给影响判断与评级，不能因为"财报信息量更大"就把重大事项埋掉。

### 3. 读原文，不要读标题

用 Read 打开非财报公告的 `.txt`，把关键数字抄下来：金额、比例、增速、期限、前置条件、生效时点。

优先精读这些类型：回购、增减持、重大合同、对外投资、募投变更、关联交易、诉讼处罚、股权激励、停复牌、异动澄清、分红方案、控制权变动。

可以略读但必须确认"无否决议案、无议案修改"的：股东会决议、法律意见书、保荐核查意见、章程与治理制度。

**扫描件（chars < 200）无法提取文本时，改用视觉方式读 PDF，或明确告知用户该份未能解析，不要跳过不提。**

### 4. 取行情基准，并做公告日对齐

```bash
python3 <skill_dir>/scripts/quote_snapshot.py --symbol 688825 --kline 15 --align 2026-10-24
```

必须拿到的四件事：

1. **公告后可交易首日的涨跌幅与量能**（`--align`）：这是市场对公告的第一次投票，是定级最硬的证据。当日公告若在盘后披露、或今天尚未收盘，`--align` 取下一个已收盘交易日，并在报告里写明。
2. **近期走势与位置**：是否创新高/新低，前期涨幅与拥挤度。注意区分盘中价与收盘价。
3. **体量与估值**：市值、PE、PB——决定"这件事的量级是否够大"。
4. **上市日期**：决定解禁、回购实施等前置条件何时满足。

近期模式下，公告可能落在窗口内任意一天，**按各自披露日逐条对齐**，不要用最新一天的反应去解释一周前的公告。

若某条公告的"字面方向"与首日走势相反，**不要强行自圆其说**，去查预期差、同业与海外联动、筹码拥挤度、结构性漏损（归母 vs 净利总额、少数股东损益）。必要时用 WebSearch 交叉验证媒体归因，但结论要用数据自己验一遍。

### 5. 定级

**读 [references/rating-framework.md](references/rating-framework.md)**，按其中的五步顺序判定，并对照"常见陷阱"表。

三条不可省略的检查：

- 信息增量：市场是否早已知道？（决议、法律意见书类通常为"已知议案的确认件" → 中性）
- 二阶导：环比/增速的变化方向，优先于同比绝对值。
- 事件时钟："提议""拟""尚需审议""获批"都不等于"已实施"；实际执行日在数月后的，短期效力要大幅折价。

输出必须是五级中的一个词，不给区间、不写"谨慎乐观"。

**评级对象是本窗口内的非财报公告整体**（多条公告时逐条给方向，再收成一个综合级）。财报本身不给级——那是 `earnings-report-deepdive` 的活。当日无任何公告时**不进入本节**，按 1.2 直接收工；不许用"中性"占位。

判断尺度拿不准时（尤其是"要不要硬凑一个观点"），读 [references/worked-example.md](references/worked-example.md) 的校准案例。

### 6. 出报告

> 第 2 步情形 2（同日财报 + 非财报）**不出本 skill 的独立 HTML**，判断并入财报报告的一节，避免双报告打架。本节只适用于非财报公告单独成篇的情形。

复制 [assets/report-template.html](assets/report-template.html)，替换占位符，保存为 `<标的><代码>_公告分析_<YYYY-MM-DD>.html`。

- 删掉用不上的区块，不留空标题。
- 上涨用红、下跌用绿（A 股习惯）。
- 报告必须包含：**检索口径（哪种模式、起止日、条数）**、公告清单、原文关键数字、行情事实、传导渠道表、**反方论证**、以及公告之外真正该盯的变量。
- 若窗口内有财报类文件（近期模式常见），在报告顶部用一行说明"其中 X 月 X 日的季报／业绩预告已转 `earnings-report-deepdive` 单独研判"，本报告只覆盖非财报公告，不复制其结论、不与其结论打架。
- 拿不到或存疑的数据，标注口径并说明局限，不要静默补齐。

### 7. 交付

`present_files` 同时给出 HTML 报告与公告 PDF 原件（PDF 排在报告之后）。

正文回复要点：口径（当日 / 近一个月）→ 评级 → 定级理由（2~3 条）→ 与直觉相反时要解释清楚 → 真正的驱动变量。控制在 30 行以内，细节留给报告。

若走的是转交分支，正文一句话交代"含业绩类文件，已转财报深研"，不再复述财报结论。

若走的是无公告分支（1.2）：**不调 `present_files`、不生成任何文件**，正文一到两句讲完标的、日期、无公告，结束。

## 反面清单（做过这些就是失职）

**口径与窗口**
- 用户没说"最近"，却把窗口拉到一周或一个月去"补全"。
- 近期模式下窗口超过一个月，或为了"看得更全"一次拉半年。
- 周一用户只问"今日公告"，自己把周末那批算进来当作"今天"。

**无公告分支（当日 0 条）**
- 不做反证（读脚本自检、失败时手动补跑）就宣布「今日无公告」。
- 已经确认无公告，还去取行情、算涨跌、给"中性"评级。
- 无公告却生成 HTML、调 `present_files`、存 PDF。
- 无公告却自行扩窗回看昨日/周末/上周，去找"其实有公告"。
- 无公告却补一段行业背景、估值讨论、"下一件大事"预告来凑长度。
- 接口自检显示异常（请求失败或全市场也是 0 条）时，仍断言"公司今日无披露"——应写"未能确认"。

**分诊**
- 把业绩预告、季报、年报当普通公告读原文、取行情、给评级——应转交 `earnings-report-deepdive`。
- 因为"公告清单里财报最显眼"就只分析财报，把同日的重组、处罚公告漏掉。
- 只按"业绩预告"四个字筛标题，漏掉"业绩预增／预亏／预盈／预减"变体和"自愿性披露公告"后缀。

**评级与报告**
- 只读公告标题就给评级。
- 把产销／经营数据快报当成财报去算利润，或把业绩预告更正件当新披露来分析。
- 把股东会决议、法律意见书之类的程序性文件说成利好或利空。
- 用披露日当天的行情解释周末公告的影响。
- 近期模式下用最新一天的反应解释窗口内一周前的公告。
- 评级给"偏正面"这类模糊词，或给区间。
- 只写支持结论的证据，不写反方风险。
- 同一只票同日生成两份互相打架的 HTML 报告。
