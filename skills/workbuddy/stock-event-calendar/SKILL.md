# 公司日历

只调一个接口：巨潮资讯网「交易信息 → 公司日历」（`https://api.cninfo.com.cn/service/tradingTips?secCode=<代码>`）。
不查公告、不推算解禁、不取行情。日历里有什么就报什么。

## 用法

```bash
PY=/Users/alex/.workbuddy/binaries/python/envs/default/bin/python
S=~/.workbuddy/skills/stock-event-calendar/scripts/company_calendar.py

$PY $S --symbol 长鑫科技
$PY $S --symbol 688825
```

## 标的选取规则

**A+H 同名时只处理 A 股，H 股一律不纳入。** 判定依据是检索结果里的 `category` 字段
（`A股`／`港股`／`资产支持证券`…），不能用 `type`——深市 A 股 000002 的 `type` 也是 `shj`，不可靠。

| 检索结果 | 处理 |
|---|---|
| 有且只有 1 只 A 股 | 直接用。若同时存在港股，在输出里注明「同名港股 XXX 未纳入」 |
| 有 ≥2 只 A 股 | 停下来列候选，让用户用代码确认 |
| 无 A 股、候选唯一（如腾讯控股） | 按唯一候选处理——用户没得选，硬报「无 A 股」反而没用 |
| 无 A 股、候选多个 | 停下来列候选 |

被忽略的标的必须写出来。用户输入「万科」时，可能是 000002 也可能是 02202，
不注明就会误以为结果对应自己想的那个市场。

## 输出规则

| 情形 | 输出 |
|---|---|
| 有事件 | 逐行 `日期  事件名  内容`，按日期升序 |
| 无事件 | `重大事件为空` |
| 接口异常 | 「未能获取公司日历（接口异常），无法判断」——**不能把查不到说成空** |
| A+H 同名 | 按 A 股输出，并附一行说明忽略了哪些港股 |

转述给用户时保持同样口径：不要把空日历说成「公司经营平稳」，也不要因为只有一条就省略。
条数少是常态，原样呈现即可。

## 口径限制（回答时一并说明）

- 公司日历**只含预排事项**，0 条并不等于没有重大事项。限售解禁、股东大会通知、回购实施等多数不在该栏目内。
- 日期是**预约**性质，可能变更，实际以公司披露为准。
- 日历可能**滞后于实际披露**（报告已发出，日历仍显示「预约披露」）。本技能不交叉核对公告，无法自行识别这种滞后。
- 港股代码检索不可靠（搜 `00981` 会命中一批无关 A 股），建议用 A 股简称或 6 位 A 股代码。

若用户要的是解禁排期、股东大会、分红登记日等日历之外的事件，本技能不覆盖，应改用公告检索的方式处理。
