# 业绩披露核查与财报深研

## 边界（先读这段，决定要不要用本 skill）

**在本 skill 范围内：**

- 业绩预告、业绩快报
- 第一季度报告、第三季度报告
- 半年度报告、年度报告
- 上述报告的摘要

**不在范围内（转交 `cninfo-announcement-impact`）：**

- 回购、增减持、股权激励、定增、可转债
- 重大合同、对外投资、资产重组
- 诉讼、处罚、问询、停复牌、异动澄清
- 股东会决议、董事会决议、法律意见书等程序性文件

### 两种检索模式——先判定用哪个

| 模式 | 触发条件 | 检索 | 分析对象 |
|---|---|---|---|
| **默认：仅当日** | 用户没特别说明（绝大多数情况） | `--days 1` | 只在今天披露的四类文件 |
| **最新数据** | 用户明确说要「最新数据」「最新财报」「最近一份报告」「上一份季报/年报」「看看它最近发的财报」 | `--latest` | 最近一个披露日的四类文件，不论多久以前 |

**默认只用当日模式。** 没听到明确的「最新」字样，就不要自作主张往前翻——用户问「今天出三季报了吗」，答案就是今天有没有，翻出两个月前的半年报属于答错题。

「最新」类措辞不明确时（如「它财报怎么样」）按默认处理；用户随后说「不是今天的，要最新的」再切模式，不要一上来就猜。

历史财报在**两种模式下**都只作对比基准——用来算同比、看趋势、判断周期位置，不单独展开分析。

## 铁律

- 只处理四类文件。同日有其他公告时，在核查结果里列出以示查全，但明确写「不属于本 skill 分析范围」，不展开解读。
- **业绩预告两种模式都必须收**。它是这四类里最容易被漏的：标题可能写作「业绩预增/预盈/预减/预亏公告」，不含「预告」二字；也可能写成「……的自愿性披露公告」。检索一律走 `is_earnings()` 的口径，**不许自己临时拼正则按「业绩预告」四个字筛**。漏掉一份业绩预告，比多分析一份回购公告严重得多。
- **当日模式**下没有这四类文件时，直接回答「今日无新的业绩报告」并结束。不做下一件大事预告，不查披露时间表，不展开历史财报，不生成报告。
- **最新模式下**，分析对象不是当天披露的，必须在报告标题、核心结论、正文首段三处都写明披露日与「距今 N 天」。不注明就等同于把旧闻当新闻，这是最严重的一类错误。
- 评级只给五级中的一个词（重大利好/利好/中性/利空/重大利空），不给区间，不写「偏正面」。评级对象是**那份财报或业绩预告本身**，不是某条公告，也不是公司整体。
- 结论建立在原文数字之上，不建立在标题或摘要之上。
- 拿不到的数据明确标注口径与局限，不静默补齐。
- 全程简体中文。

## 工作流

### 第 0 步 定时点、定模式

先确认今天几号、星期几、是否交易日。

再判模式：听用户原话里有没有「最新」「最近」这类限定。有 → 最新模式；没有 → 当日模式（默认）。

非交易日披露的公告，市场反应顺延到下一交易日——这条在两种模式下都成立，取行情时尤其要注意。

### 第 1 步 核查披露

**1.1 检索**

```bash
PY=/Users/alex/.workbuddy/binaries/python/envs/default/bin/python

# 当日模式（默认）
$PY scripts/fetch.py --keyword 纳芯微 --days 1 --no-download

# 最新模式（用户明确要最新数据时）
$PY scripts/fetch.py --symbol 688052 --latest
```

`--latest` 会从 10 天窗口起逐步扩到 30/60/120/240/400 天，命中即停，只回最近一个披露日的全部文件（全文优先、摘要并列），并打印 `⚠ 非当日披露，距今天 N 天`。看到这行警告，就必须在回答里转述它。

只给名称时先确认代码；命中多个标的手动核对，不要默认取第一条。

**1.2 当日模式 0 条时必须做反证**

否则无法排除接口延迟或市场代码错配：

```bash
$PY - <<'EOF'
import requests
H={"User-Agent":"Mozilla/5.0 Chrome/120.0","Referer":"https://www.cninfo.com.cn/",
   "Content-Type":"application/x-www-form-urlencoded; charset=UTF-8"}
r=requests.post("https://www.cninfo.com.cn/new/hisAnnouncement/query",
  data={"pageNum":1,"pageSize":30,"column":"sse","tabName":"fulltext","stock":"",
        "seDate":"2026-10-24~2026-10-24","isHLtitle":"true"},headers=H,timeout=30)
j=r.json(); print("全市场当日:", j.get("totalRecordNum"))
EOF
```

全市场当日有数百至数千条 → 接口正常，公司确实无披露。返回 0 → 换 http 重试或改用其他日期探活。

最新模式 0 条（400 天内都没有）时的反证方式不同：确认 `orgId` 没错配（同名的港股/新三板标的会让列表为空），并确认窗口内公告总数正常。这种情况多半是新股或代码解析错，写清「回溯 400 天未见业绩类文件，需人工核对」，不要说成「今日无披露」。

**1.3 把结果按标题分成两类**，只留第一类：

| 纳入（本 skill 范围） | 标题特征 |
|---|---|
| 业绩预告 / 快报 | 含「业绩预告」「业绩快报」；**还有「业绩预增」「业绩预盈」「业绩预减」「业绩预亏」四种变体——这四个词里没有「预告」二字，只按「业绩预告」筛会整类漏掉** |
| 季报 | 含「季度报告」，注意「三季度报告」与「第三季度报告」两种写法都存在 |
| 半年报 / 年报 | 含「半年度报告」「年度报告」 |
| 报告摘要 | 含「摘要」，需回溯全文 |

业绩预告的标题后缀极多，都属同一份文件，不要因为后缀陌生就当成别的公告：

- `2026年前三季度业绩预告`（素面写法）
- `2026年前三季度业绩预告的自愿性披露公告`（科创板常见，长鑫科技 2026-10-17 即此写法）
- `2026年前三季度业绩预增提示性公告` / `业绩预增的自愿性披露公告` / `业绩预增的公告`
- `2026年半年度业绩预告暨风险提示公告`（带风险提示，信息量更大，必读提示段）
- `2026年半年度业绩预告公告`（重复用词，正常）

| 排除（转交 cninfo-announcement-impact） | 举例 |
|---|---|
| 资本运作 | 回购、增减持、股权激励、定增、可转债、重组 |
| 经营事项 | 重大合同、对外投资、募投变更、关联交易 |
| 风险与治理 | 诉讼、处罚、问询、停复牌、异动澄清、股东会/董事会决议、法律意见书 |
| 例行披露 | H 股翌日披露报表、证券变动月报表（A+H 公司常见，非事件） |
| **业绩类衍生件（看着像但别用）** | `业绩预告（英）`/英文版、`业绩预告更正公告`、`业绩预告的问询函回复`、`XX会计师事务所关于……业绩预告的专项说明`、`业绩说明会`通知 |

当日只有排除类公告时，视为「无本 skill 关注的文件」，走 B 分支，但在回复里列出这些公告以示核查完整。

> `fetch.py` 输出里的 `[财务]` 标签与上表第一类的口径一致（脚本内 `is_earnings()`，含预增/预盈/预减/预亏变体），可直接作初筛。但仍要人工确认一遍标题不含上表最后一行的衍生件——那些不是新的业绩披露。

### 第 2 步 分支

**A. 命中上述四类文件之一** → 走第 3 步完整纵深分析。这是本 skill 的主战场：不要只写一句「业绩超预期」，要拆到扣非、现金流、单季环比和下一步推演。

**B. 当日模式且当日没有这四类文件**（无论是否有其他公告）→ **直接回复「今日无新的业绩报告」，然后结束。**

B 分支到此为止。具体地说，以下动作**一律不做**：

- 不做「下一件大事」预告，不推断下一份财报的披露日期
- 不查董事会会议日期、业绩说明会、预约披露时间表
- 不把最近一份历史财报翻出来做分析——包括「既然今天没有，那我就看最新的」这种念头，这属于擅自切模式
- 不生成 HTML 报告，不出评级
- 不因为「怕回答太短」而补充行业背景、估值讨论或投资建议

如果当日有排除类公告（回购、增减持等），仅列出标题与类型以示查全，一句话说明「不属于本 skill 范围」，不做解读。

> 最新模式**不存在 B 分支**：`--latest` 要么找到文件（走 A），要么 400 天都没有（按 1.2 末尾的方式说明并结束）。「最新」这个词本身就排除了「没有」的常态。

### 第 3 步 纵深分析（A 分支）

#### 3.1 先判定文件类型——它决定能分析到多深

| 文件 | 能拿到什么 | 分析深度 | 注意 |
|---|---|---|---|
| 业绩预告 | 区间值（营收/归母/扣非）、变动原因、非经常性说明 | 中 | 未审计。取区间中值，重点看**扣非与一次性损益的拆分**。**没有三大报表，走 3.2 专章，不要硬套六比率** |
| 业绩快报 | 较精确的数字，但无明细 | 中 | 与前期预告核对，看是否落在区间内 |
| 季度报告 | 三大报表 + 简表 | 中 | **通常无完整附注**，应收账龄、存货分类、合同负债明细多不可得 |
| 半年度 / 年度报告 | 全文 + 附注 | 深 | 可做完整六查与附注深挖 |
| 报告摘要 | 摘录 | 浅 | 数字不全，**必须回溯全文**，不能只读摘要 |

> 边界细节：季报常同日附带「季度经营数据公告」「计提减值准备公告」。它们不是分析对象，但可作为佐证引用（如减值的具体金额与构成），引用时注明文件名与披露日。

#### 3.2 业绩预告专项：没有三大报表，就换一套打法

业绩预告是最容易被写歪的一类——它只有区间数字加几句变动原因，硬套定期报告的六个比率，只会凑出一堆「无法计算」。

**能做（必须都做）：**

| 动作 | 具体做法 |
|---|---|
| 区间落点 | 取中值作主口径，同时保留上下限。**区间宽度本身就是信息**：跨度超过中值的 30%，说明公司自己也没把握，定级要向中性收敛 |
| 同比落点 | 用上年同期实际数算出同比的**下限/中值/上限三个数**，不要只写「同比大幅增长」。**上年同期为负时禁止算百分比**——负基数会算出 -2595% 这种荒谬值（长鑫科技 2026 前三季度预告即此情形：上年 -52.80 亿 → 本期 1310~1325 亿）。此时改写「扭亏为盈，由 -52.80 亿转为 1317.50 亿，增量 1370.30 亿」 |
| 扣非剪刀差 | 归母区间与扣非区间相减。归母远好于扣非 = 靠非经常性损益撑起来；归母差而扣非好 = 吃了一次性损失。**很多预告只给营收与归母、不给扣非**（长鑫科技 2026-10-17 即如此），此时必须写明「本预告未披露扣非，无法判断非经常性损益占比」，不许拿归母当扣非用 |
| 变动原因三分法 | 按 3.6 归类：真改善（量价齐升、结构优化）/ 一次性（补助、处置、公允价值）/ 周期项（产品价格、原材料） |
| 风险提示段 | 标题带「暨风险提示」的，提示段必须逐条摘出——那是公司自己承认的下行项，比分析师的推测更可靠 |
| 与定期报告对表 | 同一报告期的正式定期报告若已披露，**以定期报告为准**，业绩预告降级为「预告 vs 实际」的兑现度检验 |

**不能做（写明「该数据业绩预告不含」，不要编也不要估算）：**

- 毛利率、期间费用率、扣非净利率 —— 预告只给营收与利润，没有成本费用
- 应收账款周转天数、存货周转天数 —— 没有资产负债表
- 经营现金流 ÷ 净利润 —— 没有现金流量表
- 合同负债/应收/存货的前瞻推演 —— 3.9 的第 1、2 步直接跳过，只留边际利润法的粗推

**必查一件事：这份预告对应的正式报告出了没有。** 预告早于定期报告，两者信息层级不同。用 `--latest` 命中业绩预告时，先确认同一报告期是否已有定期报告：

- **没有** → 报告里必须写明「XX 季报/年报尚未披露，以下为预告区间值，未经审计」，前瞻推演只给区间，不给点估计
- **已有** → 以定期报告数字为准，业绩预告仅作兑现度对照（预告中值 vs 实际值的偏差）

> 板块差异：科创板公司常把业绩预告写成「自愿性披露公告」，那是披露安排，不代表信息量更低——恰恰相反，自愿披露通常意味着公司想让你看到。是否属于强制披露情形取决于板块与具体规则，需要时查交易所上市规则原文，不要凭印象断言。

#### 3.3 读原文：按清单抄数字

读 `references/periodic-report-checklist.md`，按它给的顺序抄七组数据：主要会计数据 → 非经常性损益 → 利润表关键行 → 资产负债关键项 → 附注深挖 → 管理层讨论 → 分季度。

顺序不能颠倒：先自己算出比率，再去看管理层怎么解释，避免被叙事框架牵着走。禁止只读标题或摘要。

> **业绩预告 / 业绩快报不适用这份清单**——它没有附注、没有三大报表，七组里有四组抄不到。这两类走 3.2 的区间打法，别拿清单硬套。

#### 3.4 双维度拆解：同比 + 环比

- **同比**：本期 vs 上年同期，用上年同期报告取数，不使用媒体转述。
- **环比**：必须拆到单季。半年报的 Q2 = H1 − 一季报；年报的 Q4 = 全年 − 前三季累计。

必算六个比率：毛利率、扣非净利率、期间费用率、应收账款周转天数、存货周转天数、经营现金流 ÷ 净利润。

周转天数一律写明口径：「平均余额 ÷ 期间收入或成本 × 期间天数，非公司披露口径」。

> 业绩预告只做同比（上限/中值/下限三档）与「上一期已知单季」的粗环比，六个比率一个都算不了——原因见 3.2。

#### 3.5 利润质量三问

见 `references/analysis-playbook.md` 第二节。核心是三个背离：归母与扣非的背离、利润与现金流的背离、增速与毛利率的背离。任一背离都要解释清楚，解释不了的就在报告里标为疑点。

#### 3.6 变化原因：真改善 / 一次性 / 周期项

逐项归因，每项带数字，并归入三类之一：

- **真改善**：费用率下降、收入结构优化、周转加快——可持续
- **一次性**：公允价值变动、资产处置、政府补助——不可持续且可能不产生现金
- **周期项**：毛利率随原材料或产品价格周期变化——要看上年趋势判断处在周期哪一端（上年提升、本年回落 = 周期切换，不是一次性扰动）

#### 3.7 内部矛盾六查

见 `references/analysis-playbook.md` 第三节。逐条对读，找到几处写几处。写作时必须注明「这是叙事张力，不等于财务造假」。

#### 3.8 风险量化

每条风险写三件事：敞口数值、触发条件、量级（高/中高/中）。按杀伤力排序。不许出现「存在一定风险」「需关注」这类无信息量的表述。

#### 3.9 前瞻推演

见 `references/analysis-playbook.md` 第四、五节，顺序是：

1. **先判合同负债是否有效**。经销+账期模式（多数芯片、元器件、消费品）常年占营收 1%~2%，无预测力，只读方向不读幅度。预收/订阅/工程模式才有强预测力。
2. **再看应收与存货**。应收：营收增速 > 应收增速且周转天数下降 = 增长质量过关。存货：备货扩张但跌价计提率同步抬升 = 公司在赌需求同时承认贬值，指出这个反向动作。
3. **最后用边际利润法推两季**，给悲观/基准/乐观三档，标注假设数值与误差来源。

推演必须配反方论证（4~5 条），写清「如果结论错了会错在哪」。

> **业绩预告走不完整这条链路**：第 1、2 步需要的合同负债、应收、存货它一个都没有，直接跳过，只保留第 3 步的边际利润法。并明确写出「因缺资产负债表数据，本次推演仅基于营收与利润区间，误差范围大于定期报告」——诚实标注局限，比硬凑一张表强。

**最新模式下推演要额外注意时滞**：如果报告已是两个月前披露的，推演起点应尽可能贴近当下（用最新行情、可比公司同期数据校准），并在推演表里写明「本推演基于 X 月披露的数据，未包含此后 N 天的新信息」。

### 第 4 步 取行情（仅 A 分支）

```bash
$PY scripts/quote.py --symbol 688052 --kline 40
```

必须拿到：最新收盘、总市值、PE(动)/PB、近 40 日高低点、区间涨跌幅。

再对比同期板块指数（半导体 ETF 512480、科创 50 000688 等），判断是个股阿尔法还是板块贝塔——这决定「市场已经定价了什么」。

**关键区别**：当日模式下问的是「披露前市场定价了什么」；最新模式下问的是「披露之后市场怎么反应了」——区间要覆盖披露日之后至今，把「财报 → 股价」的实际传导结果算出来。这是最新模式相对于当日模式的额外信息优势，别浪费。

### 第 5 步 定级

按 `references/analysis-playbook.md` 第一节的五步顺序判定：信息增量 → 二阶导 → 利润归属 → 事件时钟 → 市场投票。输出五级之一。

**评级对象只有一个：那份财报或业绩预告。** 不对单条公告评级，也不对「这家公司整体」评级。

- 命中四类文件 → 给五级之一，并说明是对哪份文件、哪个报告期的评级。
- 当日模式没有 → 写「当日无财报类披露，不适用评级」，不要硬凑一个中性。

**最新模式下定级要标注时效**：这份文件的「信息增量」已经被市场消化了 N 天，评级描述的是「这份财报本身的质量」，不是「现在买不买」。要在评级后面加一句「已披露 N 天，市场已完成首轮定价」。

**给负面评级时必须配反方论证**，避免单边叙事。

### 第 6 步 出报告（仅 A 分支）

**B 分支不出报告。** 直接进入第 7 步，用一段话回复即可。

A 分支复制 `assets/report-template.html`，写全 11 节，**删掉用不上的区块，不留空标题**：

1. 核心结论（评级 + 一句话理由 + 文件类型 + **披露日与距今天数**）
2. **结论速览：全文数据总表** —— 4~5 张表，把后面所有表格的关键信息浓缩成一页（核查结论 / 财报同比环比 / 资产负债表三指标 / 前瞻推演 / 风险量级）
3. 核查过程（可复现，含模式说明与反证）
4. 财报同比 / 环比拆解
5. 变化原因（区分真改善与一次性）
6. 内部矛盾与张力
7. 风险预警（按杀伤力量级排序，列敞口数值与触发条件）
8. 前瞻推演（区间 + 假设 + 误差来源）
9. 反方论证（如果结论错了会错在哪，5 条左右）
10. 该盯的五个数字
11. 数据来源与口径说明

**规则：**

- A 股习惯：涨用红 `#c0392b`，跌用绿 `#1e7b45`。金额默认人民币。
- 单文件、纯内联样式、可离线打开。
- **最新模式下必须在页面顶部放一条醒目提示**：「本报告分析对象披露于 YYYY-MM-DD，距报告撰写日 N 天，非当日披露」，并说明为何选用这份文件。
- 每张表下标注来源与口径。自行测算的指标写明公式并注明「非公司披露口径」。
- 推演必须给区间，标注公司是否发过指引、具体假设数值、误差来源。
- PDF 中若某表格是图片导致取不到数，在报告里明确写「该表未能提取」，不编数。
- 业绩预告类信息量小，区块 4~8 可合并成两节，不要为凑结构写空标题。

### 第 7 步 交付

**A 分支**：`present_files` 给 HTML 报告 + 涉事财报 PDF 原件（PDF 排在报告之后）。正文控制在 30 行内：评级 → 2~3 条定级理由 → 与直觉相反的要点 → 表格总结（4~5 张 Markdown 表）。最新模式下，正文第一句就要交代披露日与距今天数。

**B 分支**：不调用 `present_files`，不生成文件。正文一到三句话讲清三件事——查了什么、结果是今日无新的业绩报告、如有其他公告则列出并说明不属本 skill 范围。然后结束。

示例（不要长篇大论）：

> 已核查巨潮资讯网 2026-10-24 当日披露，纳芯微（688052）**今日无新的业绩预告、季度/半年度/年度报告或报告摘要**。
> 当日另有 1 条《关于 2023 年限制性股票激励计划第三个归属期归属结果公告》，属股权激励事项，不在本 skill 分析范围。

## 脚本

脚本路径均相对于本 skill 的 base 目录（加载时会给出）。首次使用先确认解释器可用。

| 脚本 | 用途 | 关键参数 |
|---|---|---|
| `scripts/fetch.py` | 公告列表、PDF 下载、文本提取 | `--keyword` / `--symbol`、`--days`（当日模式）、`--latest`（最新模式）、`--start/--end`、`--no-download`、`--out` |
| `scripts/quote.py` | 行情快照与日 K（仅 A 分支） | `--symbol`、`--kline`、`--align` |

解释器：`/Users/alex/.workbuddy/binaries/python/envs/default/bin/python`（已装 pypdf）。脚本仅依赖标准库。

`--out` 默认是当前目录下的 `cninfo_out/`。**在工作目录里运行**，或显式指定 `--out <工作目录>/cninfo_out`，不要把 PDF 和 JSON 落进 skill 自己的目录。

`--latest` 内部对每个时间窗口完整翻页（接口忽略 `pageSize`、恒定 30 条/页，公告密集的 A+H 公司会把定期报告挤出首页，扩窗也救不回来）。窗口序列 10→400 天，命中即停。

**两种模式共用同一套识别口径**：脚本里的 `is_earnings(title)`。核心词是 `业绩预告|业绩快报|业绩预[增盈减亏]|季度报告|半年度报告|年度报告`，再由 `EARNINGS_NOISE` 剔除英文版、更正件、说明会、会计师专项说明等衍生件。要改口径就改这一处，两个模式自动同步——不要在别处另写正则。

## 反面清单

**越界（最容易犯，因为旧习惯会把你带偏）**

- 把回购、增减持、重大合同、股东会决议拿来定级——这不在本 skill 范围，转交 `cninfo-announcement-impact`。
- 用户没说要最新，却用 `--latest` 翻出两个月前的财报当新闻分析。
- 当日没有四类文件，却把上一份财报翻出来做深度分析，凑出一篇长报告。
- 分析前一日或上月的财报，当成「当日」处理。
- 用户只问「这条公告利好利空」，却启动完整的财报拆解流程。
- 对「这家公司整体」评级，而不是对那份文件评级。

**最新模式专属**

- 用了 `--latest` 却在标题或结论里不写披露日、不写「距今 N 天」——把旧闻包装成新闻。
- 把两个月前的财报配上今天的股价，说「财报利好所以现在可以买」。
- 明明 `--latest` 打印了 `⚠` 警告，回复里却只字不提。
- 最新模式下说「今日无新的业绩报告」——措辞完全错位，应该是「回溯 N 天未见业绩类文件」。

**业绩预告专属（最容易漏、最容易写歪）**

- 只按「业绩预告」四个字筛标题，漏掉《……业绩预增公告》《……业绩预亏公告》《……业绩预盈公告》《……业绩预减公告》。
- 把《2026年前三季度业绩预告的自愿性披露公告》当成非业绩文件跳过——长鑫科技 2026-10-17 就是这种写法，它是标准的业绩预告。
- 把「业绩预告（英）」「业绩预告更正公告」「会计师事务所关于业绩预告的专项说明」「业绩说明会通知」当成新的业绩披露来分析。
- 拿着业绩预告去算毛利率、净利率、周转天数、经营现金流——它没有三大报表，这些数字不存在。
- 预告没披露扣非，就拿归母当扣非算「扣非净利率」或「非经常性损益占比」。
- 上年同期为负数还算同比百分比，写出 -2595% 这种没人看得懂的数值；应改为「扭亏为盈 + 增量金额」。
- 只报「同比大幅增长」，不给上限/中值/下限三个同比数。
- 不查同一报告期的定期报告是否已披露，就把预告区间当成已实现的业绩。
- 忽略区间宽度：跨度大说明公司自己没把握，却直接拿上限讲故事。

**通用**

- 只读公告标题或摘要就给评级。
- 用披露日当天的行情解释周末披露文件的影响（非交易日披露顺延到下一交易日）。
- 评级给「偏正面」这类模糊词，或给区间。
- 只写支持结论的证据，不写反方风险。
- 当日模式声称「当日无文件」却没做全市场反证。

**B 分支（当日无四类文件）**

- 做了「下一件大事」预告，或推断下一份财报的披露日期——这条已被明确禁止。
- 擅自改用最新模式，理由是「今天没有就看看最近的」。
- 为了显得有产出，额外补一段行业背景、估值讨论或投资建议。
- 生成了 HTML 报告或调用了 present_files。
- 把排除类公告（回购、增减持）当成分析对象解读。
- 回复超过三句话。

**A 分支（有财报）**

- 只读报告摘要不读全文——摘要数字不全，且按公司口径挑选过。
- 把业绩预告的区间中值当实际值，不注明「未审计、取中值」。
- 拿半年报数字直接和上年全年比，或拿单季和年度比。
- 归母转正就写「扭亏为盈」，不查扣非是否仍亏。
- 看到净利润增长就定利好，不看经营现金流与净利润的背离。
- 把周期项（毛利率随原材料波动）当成一次性因素，或反之。
- 矛盾检查写成「公司表述客观准确」的和稀泥，或反过来指控造假。
- 推演给单点数值，不给区间与假设。
